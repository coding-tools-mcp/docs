Coding Tools MCP Desktop 是 macOS、Windows 和 Linux 的原生应用。它把官方 `coding-tools-mcp` core 包在一个图形界面里：创建工作区、安装或选择 runtime、启动和停止服务、配置认证、通过隧道对外暴露，并查看诊断信息——全程不需要编辑配置文件。源码和原生安装包在 [coding-tools-mcp/desktop](https://github.com/coding-tools-mcp/desktop)。

![运行中工作区的 Dashboard](/images/desktop/dashboard-running.png)

如果你想要图形化路径，尤其是要连接 ChatGPT，就使用桌面应用。如果你熟悉本机 stdio 客户端配置，可以直接使用[快速开始](/zh-CN/getting-started)。

## 十分钟上手路径

第一次个人使用，最短且相对安全的路径是：

1. 安装 Desktop，并选择 **Install recommended Core**。
2. 为一个测试仓库创建工作区。
3. 先用 **Only this device** 验证本地服务。
4. 把本地配置复制到本机 MCP 客户端；只有确实需要云客户端时再开启公网访问。
5. 先用只读提示词验证，再让 AI 修改代码。

<Callout type="warn" title="工作区就是真实访问权限">
桌面应用只是便利化外壳，不是沙箱。工作区可能暴露所选文件夹内的文件编辑和命令执行能力。请先用测试仓库，确保密钥不在其中，并自己审查 diff。
</Callout>

## 安装

1. 从 [desktop releases](https://github.com/coding-tools-mcp/desktop/releases) 安装原生包，或按 desktop 仓库 README 自行构建。
2. 打开 **Settings**，选择 **Install recommended Core**。内置安装器会下载私有 Python 和所选的官方 Core，无需自己安装 Python 或 uv。新建工作区向导中的 **Use existing Core** 可以跳过这一步下载。
3. 只有需要公开分享工作区时才安装 [cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/)。仅本机使用的工作区不需要其他依赖。

![Settings：语言、外观、关闭到托盘、Core 安装管理](/images/desktop/settings.png)

**成功的表现：** 应用能打开，Settings 显示 Core 已安装，创建工作区时没有 runtime 错误。

## 创建工作区

点击侧边栏的 **New workspace**，向导共三步：

1. **Choose folder** — 工作区名称和工具可访问的绝对路径。
2. **Access** — 客户端如何连接这个工作区（见下文）。
3. **Review workspace** — 确认并创建。

![New workspace 向导的文件夹步骤](/images/desktop/new-workspace.png)

底部的 **Permission mode** 开关用于选择 `Safe`（默认值，更严格的执行检查——并不是只读）或 `Trusted`，后者需要你显式确认，只用于可信代码。

请尽量精确选择文件夹。不要只是为了省事儿选择整个 home 目录。

### 访问方式

| 访问方式 | 公网地址 | 适用场景 |
| --- | --- | --- |
| **Only this device** | 无——仅回环地址 | Claude Desktop、Cursor、MCP Inspector 等本机客户端 |
| **Temporary sharing** | Quick Tunnel `*.trycloudflare.com`，每次重启都会变化 | 短期分享和演示 |
| **Stable public access** | 通过命名 Cloudflare 隧道绑定自有域名 | 固定 URL 和浏览器登录 |
| **FRP / existing HTTPS proxy** | 外部自行管理的代理路由 | 自己维护代理的情况 |

两种 Cloudflare 方式都需要 `cloudflared`。命名隧道可以在浏览器里完成 Cloudflare 授权，并在你确认后自动创建隧道和 DNS 路由。隧道失败不会影响本地服务。

![向导的 Access 步骤，选中 Temporary sharing](/images/desktop/workspace-access.png)

## 认证方式

公开访问必须选择一种认证方式。凭据留空时，保存后会自动生成。

| 方式 | 客户端发送 | 适用场景 |
| --- | --- | --- |
| **Bearer token**（默认） | `Authorization: Bearer <token>` | 客户端可以设置请求头 |
| **Token in URL** | URL 中的 `?token=<token>` | 客户端只接受一个 URL，例如 ChatGPT 连接器或简单嵌入——同一令牌也可作为 Bearer 头使用 |
| **Username and password** | HTTP Basic 认证 | 客户端提供用户名/密码登录 |
| **Browser sign-in (OAuth)** | 使用工作区密码的 OAuth 流程 | 仅在有固定地址时可选（命名隧道或 FRP） |

![认证选项：Bearer token、Token in URL、Username and password](/images/desktop/authentication-options.png)

**Copy endpoint** 复制可直接使用的 URL——Token in URL 模式下已经带 `?token=`。Connections 页的 **Copy config** 生成对应的客户端配置，**Show credentials** 显示已保存的凭据。`?token=` 在转发给 core 前会被剥离，不会出现在 core 日志中。任何模式下 `/.well-known/` 发现接口都保持公开。

请把 connector URL、token、生成的密码和导出的配置当作密钥。不要粘贴到截图、issue、聊天或终端历史里。

## 运行与监控

**Dashboard** 显示 CPU、内存、运行时长和 Core 版本，并有 **Local service** 与 **Public access** 两张独立的健康卡片，可在此启动、停止、重启工作区。

请分开理解两张健康卡片：

- **Local service ready** 表示 core 在本机可访问。
- **Public access connected** 表示隧道/代理路径已启动；它本身并不证明客户端已经认证或完成 MCP 调用。

其他页面：

- **Connections** — 两个端点及复制按钮、**Check public address**、隧道提示和命名隧道部分。

  ![Connections 页面](/images/desktop/connections.png)

- **Activity** — 最近的工具调用，可按结果过滤。已发布的 Core 0.5.0 不暴露事件日志，因此显示 *Tool history unavailable* 属于预期；工具本身正常运行。

- **Diagnostics** — **Run checks** 检查运行时、文件夹权限和连通性；**Export diagnostics** 生成脱敏报告；运行时和隧道日志中的凭据已打码。

  ![Diagnostics 页面，显示脱敏后的运行时日志](/images/desktop/diagnostics.png)

- **Settings** — 语言（English / 简体中文）、明暗外观、**Close to tray**（关窗后服务继续运行）以及 Core 版本安装与回滚。

## 连接本机客户端

从 Dashboard 或 Connections 页复制端点或客户端配置，粘贴到 MCP 客户端中。各客户端的详细说明见[客户端配置](/zh-CN/clients)。凡是只接受 URL 的 MCP 客户端都可以用 Token in URL；下图中 MCP Inspector 通过隧道列出了工作区目录：

![MCP Inspector 连接工作区后列出目录内容](/images/desktop/inspector-list-dir.png)

对于 local-only 工作区，优先使用本机客户端和 loopback endpoint。不要只因为客户端索要 URL 就把工作区公开；许多本机客户端其实支持 stdio。

## 连接 ChatGPT

ChatGPT 的 Web 界面支持自定义 MCP server/connector，但具体文案和可用性取决于套餐、workspace 和灰度版本。它无法访问 `127.0.0.1`，所以需要公网工作区 endpoint。**Token in URL** 通常最省事，因为 ChatGPT 的自定义服务器对话框不一定能设置请求头。

<video controls playsInline preload="metadata" poster="/images/desktop/chatgpt-tutorial-zh-poster.jpg" src="/videos/desktop-chatgpt-zh.mp4" className="w-full rounded-xl border shadow-sm" aria-label="演示如何把 ChatGPT 连接到 Coding Tools MCP Desktop 工作区的带重点标注视频" />

*40 秒无配音重点演示：鼠标轨迹、点击涟漪和局部放大会标出具体控件。*

1. 在桌面应用里，用 **Temporary sharing** 或 **Stable public access** 加 **Token in URL** 认证启动一个工作区，然后在 Dashboard 或 Connections 页点 **Copy endpoint**。复制到的 URL 已经包含 `?token=`。
2. 在 ChatGPT 打开 Plugins/Connectors 区域，选择 **Add**，再选 **Add custom MCP server** 或等价的自定义连接器入口。

   ![ChatGPT Plugins 页的 Add 菜单](/images/desktop/chatgpt-add-menu.png)

3. 给服务器起个名字，把端点粘到 **Server URL**，**Authentication** 选 **No authentication**——令牌已经带在 URL 里——确认你信任这个 endpoint 后再勾选警告并创建 plugin/connector。

   ![已确认风险、可以创建的 Add custom MCP server 对话框](/images/desktop/chatgpt-dialog-confirmed.png)

4. 弹出连接卡片时点 **Connect**。之后插件出现在 **Installed** 列表里，ChatGPT 就能在对话中调用它的工具了。

   ![ChatGPT 通过 Coding Tools MCP 插件返回结果](/images/desktop/chatgpt-call-result.png)

`?token=` 参数就是授权 ChatGPT 的凭据——把这个 URL 当作密钥保管，泄露后要换新的。**Stable public access** 的工作区也可以改用 OAuth 走浏览器登录。

## 首轮验收测试

客户端连接后，不要直接开始大任务。按顺序验证：

1. 问：“List the top-level files in this workspace. Do not modify files or run commands.”
2. 确认回答与你选择的文件夹一致。
3. 让它做一个非常小、可审查的文档或正确性修复。
4. 自己在仓库里检查 `git status --short` 和 `git diff`。
5. 如果使用公网访问，确认没有凭据时 endpoint 不可用。

绿色的本地状态卡片不是验收测试。真正的验收是：真实客户端完成了一次真实、边界清晰的工作区操作。

## 后台运行与更新

启用 **Close to tray** 后，关闭窗口可以让服务继续运行。通过托盘/菜单栏图标重新打开应用、停止工作区服务或完全退出。

受管理的 Core 按版本保留。可以在 Settings 中安装新版本或回滚到已安装版本。安装新 runtime 不会无缘无故中断正在运行的工作区。

隧道和网络背景见[远程访问](/zh-CN/guides/remote-access)。故障排查请使用[故障排查](/zh-CN/troubleshooting)，先判断失败层是 Desktop、本地 core、隧道、认证、客户端，还是 workspace 权限。
